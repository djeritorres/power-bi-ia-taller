Módulo 1 · Historia

De un archivo binario a un modelo que la IA puede editar

El recorrido: TMSL → TMDL → PBIP → PBIR → MCP. Entenderlo explica por qué hoy podemos construir un reporte completo con Claude.

Punto de partida

El .pbix: una caja cerrada

📦 .pbix BINARIO

Un único archivo con todo junto. Para Git o una IA, es una caja negra.

Ventas.pbix  (1 solo archivo)
 ├ DataModel   ← binario comprimido
 ├ Report/Layout ← un JSON enorme
 ├ DataMashup  ← Power Query
 ├ Connections
 └ Metadata
Consecuencia: difícil de leer, de editar y casi imposible de trabajar entre varias personas.

El formato de siempre

TMSL: el lenguaje del model.bim

TMSL son las siglas de Tabular Model Scripting Language (Lenguaje de scripting de modelos tabulares): el formato JSON en el que se guardaba el model.bim.

  • Un único archivo, a menudo muy grande, con todos los metadatos del modelo
  • Difícil de leer y de editar, y un obstáculo para trabajar varios desarrolladores sobre el mismo modelo

🧾 model.bim TMSL · JSON

Al extraer el modelo salía un único JSON, muy grande.

{
  "name": "SemanticModel",
  "model": { "tables": [
    { "name": "Ventas",
      "columns": [ ... ],
      "measures": [ ... ] },
    ... cientos de líneas más

Antes de TMDL

TOM: la API detrás del modelo

TOM son las siglas de Tabular Object Model (Modelo de Objetos Tabulares). Es una biblioteca de .NET de Microsoft que permite administrar y modificar, mediante programación, la estructura de los modelos semánticos (modelos tabulares).

¿Para qué sirve?

⚙️ Automatización

Crear, actualizar y modificar tablas, columnas, relaciones y medidas DAX de forma automática mediante código (C# o .NET), en lugar de hacerlo manualmente en la interfaz.

🧰 Herramientas externas

Es la base que usan aplicaciones muy populares de la comunidad para extender Power BI, como Tabular Editor o ALM Toolkit.

🔌 Conexión por XMLA

XMLA es el protocolo para hablar con el motor del modelo. En Power BI Desktop, TOM se conecta al motor local de tu archivo. En el servicio, usa el punto de conexión XMLA (Premium o Fabric).

Después, TMDL se sumó como métodos nuevos de TOM, y hoy el MCP de modelado sigue apoyándose en TOM y ADOMD.NET.
Analogía · TOM y TMSL

TOM y TMSL: el restaurante

Imagina que el modelo es una cocina y quieres pedirle un cambio. Hay dos formas de hacer el pedido.

Ejemplo: «20 mesas con el mismo plato, sin cebolla». Con TOM lo pides en código y envía solo lo que cambió; con TMSL escribes tú la hoja de pedido. Ambos llegan por XMLA.
2023 · Preview público

Nace TMDL

TMDL son las siglas de Tabular Model Definition Language (Lenguaje de definición de modelos tabulares): un formato de texto legible para definir el modelo.

  • Formato legible, con sintaxis tipo YAML
  • YAML (YAML Ain't Markup Language): formato de texto para escribir datos donde la sangría indica qué va dentro de qué. Como una ficha: cada línea es «campo: valor». 
    alumno: Ana
curso:
    nombre: Power BI
    tema: TMDL
  • Estructura de carpetas: un archivo por objeto del modelo
  • Pensado para control de versiones y varios desarrolladores
createOrReplace

	table Palabras

		column Palabra
			dataType: string
			isNameInferred
			sourceColumn: [Palabra]

		partition Palabras = calculated
			mode: import
			source = DATATABLE("Palabra", STRING, {{"DAX"}, {"VIVE"}})

Antes y después

La misma tabla, dos formatos

TMSL ANTES · JSON

  "name": "Ventas",
  "columns": [ { "name": "Monto" } ],
  "measures": [ {
    "name": "Ventas Totales",

    "formatString": "#,0" } ]

Dentro de un model.bim gigante

TMDL AHORA · TEXTO

table Ventas
    column Monto
    measure 'Ventas Totales' =
        SUM(Ventas[Monto])

Junio 2023 · Preview

Desktop Developer Mode y el .pbip

PBIP son las siglas de Power BI Project (Proyecto de Power BI): guardar el trabajo como una carpeta de archivos de texto en lugar de un solo archivo binario.

  • Nueva opción: guardar como Power BI Project (.pbip)
  • Modelo y reporte como archivos de texto, no binarios
  • Habilita Git, revisión de código y CI/CD
  • Desktop no trae Git nativo: se usa una herramienta externa como VS Code
.pbip
GA desde el 1 de septiembre de 2026: ya no es preview, es la forma estándar de guardar el proyecto.
2024 · TMDL + PBIR

El proyecto se vuelve carpeta de texto

PBIR son las siglas de Power BI enhanced report format (Formato mejorado de reporte de Power BI): guarda el reporte como archivos JSON.

  • TMDL en PBIP (preview): model.bim se reemplaza por la carpeta definition
  • PBIR (junio 2024): el reporte pasa a JSON por página, visual y marcador
  • Cada archivo tiene esquema JSON público: VS Code valida mientras editas
  • Un proyecto PBIP contiene ambos: el modelo en TMDL y el reporte en PBIR, cada uno en su propia carpeta
Ventas.Report/
  definition.pbir  ← enlaza al modelo
  definition/
    report.json  ← filtros y formato del reporte
    version.json
    pages/
      pages.json  ← orden, página activa
      Página1/
        page.json  ← filtros de la página
        visuals/
          Visual1/
            visual.json  ← posición, formato, consulta

Ecosistema · Herramientas externas

Antes de la IA, ya había herramientas externas

Tabular Editor TE2 gratis · TE3 de pago

Edita los metadatos del modelo sin cargar datos: ediciones masivas, scripts C#, grupos de cálculo, perspectivas, reglas de buenas prácticas.

DAX Studio GRATIS

Escribe y ejecuta consultas DAX, mide tiempos y analiza el rendimiento. Se abre desde Herramientas externas ya conectado al modelo.

ALM Toolkit MAQ SOFTWARE

Compara modelos, fusiona cambios y despliega solo la diferencia (metadatos) sin republicar todo.

Measure Killer BRUNNER BI

Detecta medidas, columnas y tablas sin uso. Puede borrar medidas o generar el script y el código M para quitar columnas.

Bravo SQLBI · GRATIS

Analiza el modelo, formatea DAX masivamente y exporta datos. Incluye el análisis de tamaño tipo VertiPaq Analyzer.

pbi-tools

Herramienta de línea de comandos de la comunidad para llevar proyectos Power BI a control de versiones.

Cómo se conectan

Todas hablan con el modelo por la misma puerta

  • Desde 2020, librerías de Microsoft permiten a estas herramientas integrarse con Power BI Desktop
  • Se registran con un archivo JSON y aparecen en la cinta Herramientas externas
  • Desde 2021 también editan modelos publicados vía endpoint XMLA
  • El MCP de modelado sigue las mismas reglas que las herramientas externas
Idea clave: la IA no reemplaza estas herramientas; usa la misma puerta (TOM) y las complementa.
Oct–Nov 2025 · Preview público

Power BI Modeling MCP Server

MCP son las siglas de Model Context Protocol (Protocolo de contexto de modelos): el estándar abierto que conecta la IA con herramientas y datos.

  • Antes del MCP, la IA era solo un chat: no conocía tu modelo ni podía leerlo o modificarlo directamente
  • Repositorio de Microsoft creado el 16 oct 2025; lanzado en Ignite 2025
  • Conecta agentes de IA a tu modelo: Desktop, Fabric o archivos PBIP
  • Tablas, relaciones, medidas, operaciones masivas y validación de DAX
  • Usa las mismas APIs de siempre (TOM y ADOMD.NET), con acceso estandarizado

⚠️ Alcance

Solo modela. No modifica páginas ni visuales del reporte: esa parte se hace sobre los archivos PBIR.

Analogía · MCP

El control remoto del modelo

Ejemplo: quieres crear la medida Margen %.

El MCP no decide ni piensa: solo aprieta el botón exacto que el cliente de IA le indica, sobre el televisor real.

🧭 En resumen

Como el motor valida cada botón del MCP al instante, los cambios de modelo son confiables. Para páginas y visuales (PBIR) no hay motor que valide mientras se escribe el JSON: por eso ahí conviene apoyarse en un skill (reglas y ejemplos en AGENTS.md/CLAUDE.md) y siempre confirmar el resultado abriendo Power BI Desktop.
